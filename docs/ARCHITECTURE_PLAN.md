## 一、系统愿景与设计哲学

### 1.1 破除五大孤岛
当前用户面临最大的学习困境在于五个维度的严重割裂：
- **项目孤岛**：看代码无头绪，缺少可视化架构蓝图与调用链索引。
- **知识孤岛**：语雀文档、C++ 语法、Linux 理论停留在散落的笔记中。
- **任务孤岛**：Google Tasks 日程与实际代码学习脱节，变成机械打卡。
- **证据孤岛**：学完没有留下跑通的测试、Debug 日志、Git 提交记录。
- **求职孤岛**：面试时无法自如口述项目技术难点与底层原理。

本系统的核心使命是建立闭环传输链路：

                  ┌──────────────────────┐

                  └──────────┬───────────┘

                             ↓
              ┌──────────────┴──────────────┐
              ↓                             ↓
         源码研读/调试                  语雀/书籍理论
       (muduo/C++/Linux)               (底层原理与设计)
              └──────────────┬──────────────┘
                             ↓

## 三、最终视图结构与导航定义

### 1. Dashboard (大盘与驾驶舱)
- **Today's Primary Mission**：基于当前未掌握的 CppAIService 核心模块自动推荐当日主线（S 级任务，3h），附带“为什么做”、“关联源码”、“验收标准”。
- **Google Tasks 实时日程映射**：完整对应用户的 IT、阅读、就业三维日常，支持直接勾选完成。
- **全站指标总览**：项目掌握度、代码阅读行数、Evidence 归档数、连续攻坚天数、专注时长分布。
- **快速全局检索栏**：输入任意技术词（如 `EventLoop`, `epoll`, `MCP`, `RabbitMQ`）即时定位代码、文档、任务与面试题。

### 2. Project (CppAIService 核心工坊)
- **架构全景拓扑 (Interactive Canvas)**：
  - 动态呈现四层架构：客户端层 ➔ 业务服务层 (`HttpServer`/`ChatServer`) ➔ 数据消息层 (`MySQL`/`RabbitMQ`) ➔ 推理平台层 (`AIStrategy`/`ONNX`/`Baidu`).
  - 点击节点即展开该模块的责任、文件、线程模型、依赖与高频面试深挖点。
- **模块导航树 (Source Navigator)**：
  - `HttpServer` (主从 Reactor, HTTP Codec 状态机, 动态路由, 会话管理, 中间件, SSL, 连接池).
  - `ChatServer` (AIStrategy 策略工厂, 轻量 MCP 协议与工具注册, RAG 检索, 异步入库, 多模态识别).
- **项目成长轨迹 (Project Timeline)**：
  - 记录学习、修改、Bug 修复、Commit 与压测记录。

### 3. Knowledge (语雀知识库与考点矩阵)
- **Yuque Explorer**：
  - 程序员 Carl《HTTP服务框架》17 篇知识库完整离线浏览与目录树索引。
  - 保留原始链接、标题、字数、更新时间与行级关联源码入口。
- **语法 ➔ 工业源码对照矩阵**：
  - 完整保留并扩展原系统的 C++11/14 语法映射（RAII、智能指针、移动语义、std::bind 回调等）。

### 4. Learning (统一学习中心)
- **muduo 28 天原版攻坚流水线**：
  - **100% 完整保留原版 28 天任务与自测题**，确保既有学习不丢失。
- **算法手撕 Lab (Daily 3 Problems)**：
  - 对齐用户日常“每日 3 道”，记录题号、考点、独立完成度、时空复杂度与口述思路。
- **书卷研读 (Books Companion)**：
  - 追踪《Linux多线程服务端编程》（10页/天）与《鸟哥的私房菜》（10页/天），直接锚定到项目实践场景。
  - 阅读通识（《非暴力沟通》、《从零开始学习金融学》、《图解博弈论》）低打扰追踪。

### 5. Tasks (统一任务系统)
- **任务层级与优先级**：
  - S 级：CppAIService 核心攻坚 (3h)
  - A 级：算法 3 道 + Linux/服务端编程 (2h)
  - B 级：C++ / Agent 八股 (30min)
  - C 级：通识阅读 + 牛客行情 (1h)
- 动态降级保护：当时间受限时，自动压缩 C 级与 B 级，确保 S 级与 A 级主线推进。

### 6. Evidence (工程证据与踩坑档案)
- **事故与踩坑档案 (Incident Archive)**：
  - 原有踩坑库升级为“故障现象 ➔ 底层根因 ➔ 错误代码 ➔ 正确修复 ➔ 工程铁律”。
- **工程验证凭证 (Evidence Ledger)**：
  - 记录单元测试通过输出、性能压测指标（QPS/RT）、GDB 调试日志、Git Commit 哈希。

### 7. Career (求职与面试工坊)
- **面试题库与追问生成器**：
  - 结合项目真实源码自动对应八股与深挖考点（如：为什么在 Reactor 中使用 `eventfd` 唤醒？智能指针在异步网络库中的线程安全隐患？）。
- **STAR 法则简历导出器**：
  - 将 Evidence 自动提炼为高含金量的简历 Bullet：“基于 muduo Reactor 架构自研 C++ HTTP 服务框架，利用 RabbitMQ 将数据库写入异步化，吞吐量提升至 XXX...”。

### 8. Settings (数据与系统诊断)
- 数据版本迁移工具（SchemaMigrationV6）。
- JSON 完整导出冷备份与导入恢复。
- 数据健康度检查（检测孤儿任务、死链）。

## 四、加法改造技术路线与向后兼容设计

### 4.1 数据无损存储演进
- 保留 `muduo_v5_data` 核心字段结构，平滑升级到 V6 统一模型。
- 新增 `cppai_modules`, `yuque_articles`, `algorithm_records`, `evidence_items`, `google_tasks` 命名空间。
- 初始化加载时执行自动数据补齐，保证无论从 V4、V5 或初始状态进入，用户既有数据毫发无损。

### 4.2 技术栈延续性
- 继续采用轻量高效的单页结构（纯原生 ES6 模块化 + Tailwind CSS），免去笨重复杂的构建负担，支持双击直接在浏览器运行或 GitHub Pages 极速访问。
- 遵循单一职责拆分 JS：
  - `dataset-28days.js` (保持不变)
  - `dataset-mappings.js` (保持不变)
  - `dataset-cppai.js` (新增 CppAIService 与语雀全量数据集)
  - `timer.js` (保持专注计时核心)
  - `app.js` (统一调度与多视图渲染)
